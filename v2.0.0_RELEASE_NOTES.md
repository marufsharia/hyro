# Hyro v2.0.0 Release Notes

## 🎉 Major Release: Filament-Style Asset Architecture

This is a major release that introduces a complete overhaul of the asset management system, inspired by Filament's architecture. This release includes breaking changes but provides significant improvements in developer experience and package maintainability.

## 🚀 What's New

### 1. Centralized Asset Management

**New `AssetManager` Class**:
```php
use Marufsharia\Hyro\Core\Support\Assets\AssetManager;

// Register assets programmatically
AssetManager::registerStyle('my-style', asset('css/custom.css'));
AssetManager::registerScript('my-script', asset('js/custom.js'));
```

### 2. Simplified Blade Directive

**New `@hyroAssets` Directive**:
```blade
<head>
    @hyroAssets  {{-- Renders all registered assets --}}
</head>
```

Replaces the need for multiple directives:
- ~~`@hyroCss`~~ (still works for backward compatibility)
- ~~`@hyroJs`~~ (still works for backward compatibility)

### 3. Build to `/dist` Directory

Assets are now built to `/dist` instead of `/public/build`:
- Cleaner separation of source and built assets
- Pre-built assets committed to repository
- No build step required for end users

### 4. Zero-Configuration Installation

**New `hyro:install` Command**:
```bash
php artisan hyro:install
```

One command to:
- Publish configuration
- Publish assets
- Publish migrations
- Add trait to User model

### 5. CDN Fallback System

Automatic fallback to CDN if built assets are unavailable:
- Tailwind CSS from `cdn.tailwindcss.com`
- Alpine.js from `cdn.jsdelivr.net`
- Works immediately after `composer require`

### 6. Plugin Asset Support

Plugins can now register their own assets:
```php
AssetManager::registerStyle('my-plugin', asset('vendor/my-plugin/css/plugin.css'));
AssetManager::registerScript('my-plugin', asset('vendor/my-plugin/js/plugin.js'));
```

### 7. Improved Asset Helper

**New `AssetHelper` Class**:
```php
use Marufsharia\Hyro\Core\Support\Assets\AssetHelper;

$cssUrl = AssetHelper::getCssUrl();  // Get versioned CSS URL
$jsUrl = AssetHelper::getJsUrl();    // Get versioned JS URL
```

## 💥 Breaking Changes

### 1. Asset Publishing Path Changed

**Before (v1.x)**:
```
public/vendor/hyro/
├── manifest.json
├── assets/
│   ├── hyro-[hash].css
│   └── hyro-[hash].js
├── css/
│   └── hyro-alert.css  (fallback)
└── js/
    └── hyro-alert.js   (fallback)
```

**After (v2.0)**:
```
public/vendor/hyro/
├── manifest.json
├── css/
│   └── hyro-[hash].css
└── js/
    └── hyro-[hash].js
```

### 2. Vite Configuration Changed

**Before (v1.x)**:
```js
export default defineConfig({
    plugins: [
        laravel({
            input: ['resources/css/hyro.css', 'resources/js/hyro.js'],
        }),
    ],
});
```

**After (v2.0)**:
```js
export default defineConfig({
    plugins: [
        laravel({
            input: ['resources/css/hyro.css', 'resources/js/hyro.js'],
            buildDirectory: 'dist',
        }),
    ],
    build: {
        outDir: 'dist',
        manifest: true,
    },
});
```

### 3. Asset Publishing Command Updated

**Before (v1.x)**:
```bash
php artisan vendor:publish --tag=hyro-assets
```

**After (v2.0)**:
```bash
php artisan hyro:install
# or
php artisan hyro:publish-assets
```

### 4. Removed Raw Asset Fallbacks

The package no longer publishes raw CSS/JS files as fallbacks. Instead, it uses CDN fallbacks.

**Removed**:
- `public/vendor/hyro/css/hyro-alert.css`
- `public/vendor/hyro/js/hyro-alert.js`

**Replaced with**: CDN fallbacks (Tailwind CSS, Alpine.js)

## 🔄 Migration Guide

### Step 1: Update Composer

```bash
composer update marufsharia/hyro
```

### Step 2: Reinstall Assets

```bash
php artisan hyro:install --force
```

Or manually:
```bash
php artisan hyro:publish-assets --force
```

### Step 3: Update Your Layouts

**Before**:
```blade
<head>
    @hyroCss
    @livewireStyles
</head>
<body>
    @hyroJs
    @livewireScripts
</body>
```

**After**:
```blade
<head>
    @hyroAssets
    @livewireStyles
</head>
<body>
    @livewireScripts
</body>
```

### Step 4: Update Plugin Asset Registration (if applicable)

If you have custom plugins, update them to use `AssetManager`:

```php
use Marufsharia\Hyro\Core\Support\Assets\AssetManager;

public function boot()
{
    AssetManager::registerStyle('my-plugin', asset('vendor/my-plugin/css/plugin.css'));
    AssetManager::registerScript('my-plugin', asset('vendor/my-plugin/js/plugin.js'));
}
```

### Step 5: Clear Caches

```bash
php artisan view:clear
php artisan cache:clear
```

## 🎯 Benefits

### For End Users

1. **Simpler Installation**: One command installs everything
2. **No Build Requirements**: No need for Node.js or npm
3. **Faster Setup**: Pre-built assets included in package
4. **Automatic Updates**: Assets auto-publish on package update
5. **CDN Fallback**: Works even without published assets

### For Plugin Developers

1. **Easy Asset Registration**: Programmatic API for registering assets
2. **No Manual Publishing**: Assets registered automatically
3. **Conflict Prevention**: Unique asset names prevent conflicts
4. **Extensible**: Easy to add custom assets

### For Package Maintainers

1. **Cleaner Structure**: Separation of source and built assets
2. **Better Version Control**: Built assets committed to repo
3. **Reduced Support**: Fewer installation issues
4. **Filament Compatibility**: Similar architecture to popular packages
